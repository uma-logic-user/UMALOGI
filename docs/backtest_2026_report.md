#### ⚠️ トリガミ防止フィルターの過剰稼働について

**現状**: 1,025レース中わずか **20件（約2%）** しか馬連を生成しなかった。

**原因**: 現実装のフィルター条件が理論上の閾値に対して厳格すぎる。

```python
# 現実装（Harville確率ベース）
best_prob <= (1.0 - take) / n_combos
# 馬連7点: threshold = (1 - 0.225) / 7 = 0.1107
# 12〜18頭立てでは最良馬連確率が0.11未満になりやすく、ほぼ全件スキップ
```

**仕様通りの実装（推定払戻ベース）**:
```python
# 仕様: estimator.scale(bt) × axis_odds > n_combos × margin
# 馬連7点(margin=1.5): 6.0 × axis_odds > 10.5 → axis_odds > 1.75
# 実質ほぼ全レース通過（大穴軸以外）
```

**次期改善ポイント**: フィルターロジックを仕様通りの推定払戻ベースに変更することで、シミュレーション母集団を大幅に拡大できる（次フェーズで対応予定）。

## 5. 分析・考察

### 5-1. 強みのある戦略

**卍モデルの単勝・複勝が唯一の安定した正収支ゾーン。**  
卍（暫定）単勝の ROI 247.6%（+¥27,460）、卍（暫定/直前）複勝の ROI 156〜177%（+¥40,000超）は再現性のある正収支を示している。これは EV≥1.1 の閾値フィルターが単・複に対して機能していることを意味する。

### 5-2. 深刻な課題領域

| 課題 | 現状 | 原因仮説 |
|---|---|---|
| **馬連・馬単 ROI≒0%** | 的中率 0〜3% | 軸1頭×相手5頭のフォーメーションが波乱を取りこぼしている |
| **三連単 0的中** | ROI 0%（全バリアント） | 1着固定12点では点数不足。波乱レースで軸馬が飛ぶと全滅 |
| **本命三連単 105,600円全損** | 0的中 / 176件 | フォーメーション12点の絞りすぎによる構造的問題 |
| **Oracle 三連複 ROI 14.8%** | 払戻＜投資 | Harville確率最大化でも JRA 控除率(27.5%) には勝てない |

### 5-3. rank=2/3 補完の限界

rank=2/3 が正確に補完できているのは全1,200レース中 **1,090レース（90.8%）** のみ。残り約110レースでは三連複・三連単の的中判定が不完全な可能性がある。本レポートの的中率は若干の過小評価となっている可能性がある。

### 次フェーズ：フィルター改善

**優先度 HIGH**: トリガミフィルターを現行のHarville確率ベースから、仕様通りの推定払戻ベースに変更する。

```python
# 変更前（Harville確率ベース — 過剰に厳しい）
best_prob <= (1.0 - take) / n_combos

# 変更後（推定払戻ベース — 仕様通り）
estimated_payout = estimator.scale(bet_type) * axis_odds1 * 100
total_investment = len(combos) * 100
return estimated_payout <= total_investment * MARGIN[bet_type]
# MARGIN: 馬連/三連複=1.5, 馬単=1.2, 三連単=1.0
```

この変更により、推定母集団が 20件 → 800件超 に拡大し、実質的な統計検証が可能になる。

### 三連単点数不足への対応

現行12点（4パターン × 3相手）では 2026年データで 0的中。  
対応方針: 相手候補を AITE_N=3 → AITE_N=5〜7 に拡大して 20〜28点化を検討。

```
目標: 三連単 ROI ≥ 100% に必要な的中頻度
  三連単平均払戻 ≈ ¥10,000 (実測 2026年データ)
  20点買い = ¥2,000/レース
  必要的中率 = 2,000 / 10,000 = 0.20% (500レースに1回)
  1,025レース中 → 2的中で損益トントン
```
