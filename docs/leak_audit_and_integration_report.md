## タスク1: 特徴量 Ablation によるリーク監査と修正

### 1.1 監査手法

`scripts/ablation_leak_audit.py`（新規）:
① 単一特徴量 AUC スキャン（各数値列単独の test AUC でリーク源を直接特定）
② グループ別 ablation（特徴量グループを除外して AccuracyModelV2 を再学習）。
train 300レース(2024-01〜2025-10) / test 150レース(2025-10〜2026-06)・キャッシュ方式。

### 1.2 特定したリーク（決定的証拠）

**単一特徴量 AUC スキャン（修正前）**:

| 特徴量 | 単独AUC | 判定 |
|---|---|---|
| win_rate_distance_band_zscore | **0.9574** | 🚨 リーク確定 |
| win_rate_distance_band_rank | 0.9483 | 🚨 |
| win_rate_surface_zscore | 0.9477 | 🚨 |
| win_rate_all_zscore / rank / 素値 ほか計9列 | 0.90〜0.95 | 🚨 |
| recent_rank_mean 系 | 0.78 | ⚠️ 同経路で軽度混入 |
| shin_prob 等オッズEV系 | 0.56 | 正常（当初仮説は外れ） |

「馬の過去勝率」が単独で AUC 0.95 を出すことは原理的に不可能 → **勝率集計に
当該レース自身と未来レースの着順が混入**していると断定。

### 1.3 根本原因（src/ml/features.py）

`FeatureBuilder` には2つの特徴量生成経路があり、リーク防御の実装が非対称だった:

| 経路 | 用途 | `_get_horse_stats_bulk` 呼び出し |
|---|---|---|
| `build_race_features_for_simulate` | **本番モデル学習**（models.py:227） | `exclude_race_id` + `race_date` あり ✅ |
| `build_race_features`（entries 由来） | 本番**推論**＋一部バックテスト | **両引数なし** ❌ |

本番推論（未来レース）では結果が未存在のため実害ゼロだが、
`accuracy_model_v2.build_training_data` / `evaluate_hybrid_ensemble` が
**歴史レース**に `build_race_features` を使ったことで、
win_rate 系に「当該レースの勝敗そのもの＋未来の成績」が混入した。

> ✅ **本番モデル（honmei/卍/複勝/Pure_EV）は学習・較正とも simulate 経路のため無傷**。
> predictions テーブル・実弾成績への影響は無い（過去の OOS 報告のうち
> backtest_v2 系は独自のリーク防御を持ち W-070 で監査済み）。

### 1.4 実施した修正

1. **src/ml/features.py**: `build_race_features` の `_get_horse_stats_bulk` 呼び出しに
   `exclude_race_id=race_id, race_date=race_date` を付与。本番推論は挙動同一
   （未来レースに結果は存在しない）、歴史レースでのみリークを遮断する普遍修正。
2. **tests/test_features.py**: 旧テスト `test_win_rate_allが計算される` は
   「当該レース自身の1着が勝率に混入する」リークを“正常”として固定していたため、
   過去1走(2着)を投入し**当該レースで1着でも win_rate_all=0.0** を検証する
   リーク回帰テストへ書き換え。

### 1.5 修正後の「真の」性能（同一データ・同一手順で再計測）

**単一特徴量 AUC（修正後）**: 最高でも recent_rank_mean_zscore 0.733。
win_rate 系は 0.56〜0.62 の正常域へ収束（0.957→0.62）。

**AccuracyModelV2（300レース学習・Top2フラット単勝）**:

| 指標 | 修正前（リークあり） | 修正後（真値） |
|---|---|---|
| test AUC | 0.9505 | **0.6644** |
| Top2 的中率 | 39.0% | **13.3%** |
| Top2 ROI | 381.5% | **81.6%** |

### 1.6 修正後ハイブリッド再検証の実測値（train 400 / test 200・単勝フラット）

| 戦略 | 修正前（リークあり） | **修正後（真値）** |
|---|---|---|
| 全買い(honmei勝率上位2頭) | n=400 ROI 130.4% | n=400 的中33.8% **ROI 179.1%**（AUC 0.8813） |
| EVモデル単体(EV≥1.0) | n=1,532 ROI 89.2% | n=1,556 的中5.4% **ROI 92.5%** |
| AccuracyModel単体(L1) | n=92 的中72.8% ROI 629.7% | n=46 的中13.0% **ROI 41.3%**（AUC 0.6752） |
| 二階層アンサンブル(L1∩L2) | n=35 的中65.7% ROI 1173.1% | n=10 的中10.0% **ROI 76.0%** |

- 二階層（76.0%）は Accuracy単体（41.3%）こそ上回るが **EV単体（92.5%）に劣後**し
  黒字ラインにも届かない。
- 全買い 179.1% は honmei 上位2頭の少数大穴依存（過去の OOS と同じ高分散パターン）で
  あり、ベットサイズ規律なしには実弾根拠にならない。

### 1.7 結論

- **AUC 0.944 / ROI 1173% は 100% リークの幻影**だった。W-071 の鉄則
  「良すぎる数値を疑え」が3たび機能（W-070 加速力リーク→今回 win_rate リーク）。
- AccuracyModelV2 の真の実力（AUC 0.66 @300レース学習）は本番 honmei
  （honest AUC ≈ 0.82・全件学習）に遠く及ばず、**ハイブリッドアンサンブルの
  本番昇格は棄却**。再挑戦するなら全件学習＋較正＋再OOSが前提。

## タスク2: 見送り（No-Bet）判定の有効性検証

`scripts/validate_no_bet_filter.py`（新規）で実弾確定 P&L **549ベット/438レース**に遡及適用:

| chaos閾値 | 見送りレース | 適用後ROI（適用前91.9%） | 判定 |
|---|---|---|---|
| 0.42（既定） | 1/438 (0.2%) | 92.0%（+0.1pt） | ✅ 微益（防げた不的中1件・機会損失0件） |
| 0.35 | 1/438 | 92.0%（+0.1pt） | ✅ 同上 |
| 0.30 | 2/438 | 83.1%（-8.9pt） | ❌ 逆効果 |
| 0.20 | 6/438 | 83.4%（-8.5pt） | ❌ 逆効果 |
| 0.15 | 14/438 (3.2%) | 83.9%（-8.1pt） | ❌ 逆効果 |

**結論（仮説の棄却）**: 「混戦レースを見送れば ROI が上がる」仮説は実データで**棄却**。
現行実弾モデル（卍複勝/Pure_EV_Edge）は**混戦レースの市場の歪みこそが利益源**であり、
カオス回避は利益源を切る行為だった。対応: W-079 を ⚪保留へ降格し、モジュールの用途を
①オーバーラウンド異常（データ供給異常）検知 ②E2E出力の「見送り」演出に限定。
シャドー運用昇格は中止（誠実評価: 作った機能でも効かないものは結線しない）。

## タスク3: 全機能統合 E2E テスト

`scripts/e2e_final_prediction.py`（新規）— リーク修正済み AccuracyModelV2 ×
見送り判定 × 全券種EVオプティマイザを結合し、実レース（阪神12R・2026-06-07）で
「SNS無料予想」「サブスク詳細分析」の2出力を生成。

### 統合中に発見・修正した品質問題

未較正の AccuracyModelV2 確率（class_weight=balanced で過大）を直接オプティマイザへ
渡すと **EV 10〜14 の幻影**が出た（W-066 と同型）。v1.7.2 で OOS 実証済みの
**市場アンカー型ブレンド（blend_with_market）** を勝率推計に適用して解消
（未検証係数の発明ではなく、検証済み本番メカニズムの再利用）。

### E2E 実行結果（✅ 全ステップ正常）

```
対象: 202609030212 阪神12R 3歳以上1勝クラス (2026-06-07)
Step1 勝率推計: AccuracyModelV2(4,075行学習) + 市場ブレンド
Step2 見送り判定: skip=False (chaos=0.0)
Step3 全券種スキャン: 高EV候補8点 / フォーメーション2型
Step4 出力: outputs/e2e/202609030212/{sns_free.md, subscription_detail.md}
```

生成物の品質（ブレンド後）: EV レンジ 1.78〜2.16（現実的な歪み水準）・
三連単 軸8×相手[3-10-11] 6点 / 三連複 軸[3-8] 2点に自動要約。
SNS 無料側は ◎○▲3頭＋勝率＋サブスク導線フレーズのみ（盾と矛の分離を維持）。

### 安全境界の再確認

- E2E 出力は**分析・コンテンツ用**。bet_policy の実弾ロック（単複のみ）は不変。
- features.py 修正は本番推論で挙動同一（回帰テスト全件で確認）。
