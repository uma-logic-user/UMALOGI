## 0. 辛口現状分析：「自分用ツール」と「顧客に金を払わせる商材」の差

### 0-1. 収益性の正直な評価

UMALOGIの2026年バックテスト全体ROIは **49.9%（-¥454,494）** である。  
「+87万円の純利益」はある1日の突出した結果であり、**年間累計では負けている**。

| 評価軸 | 実態 |
|---|---|
| 全モデル合算ROI | **49.9%（投資の半分が消える）** |
| 勝ちパターン | 卍(直前)複勝 ROI 177%、卍(暫定)複勝 ROI 156% のみ |
| 負けパターン | 三連単・三連複・HitFocus は全年でROI 20〜70%（大赤字） |
| 2025年 | rankデータ汚染で信頼できる検証不可 |
| 2024年 | race_results復元率 41.2%（6割は証拠なし） |

**商用化の前提条件**：「卍複勝モデル単体」を主力商品として切り出し、その実績だけを前面に出す。三連単・HitFocusは現状「お試し枠」以上に見せてはならない。顧客を騙す展開は長期的なブランド毀損を招く。

---

### 0-2. 商品力の5大欠陥

#### 欠陥 1：「なぜその馬か」が一切説明されない

現在の出力は `combination_json: [[3]]` という生データのみ。  
顧客が支払うのは「答え」ではなく「納得感（ストーリー）」である。  
**3番が来る理由を3行で語れなければ、500円の値打ちもない。**

#### 欠陥 2：実績の見せ方が素人以下

- ダッシュボードはエンジニア向けUI（的中率・ROI表示は内部管理用）
- 「65.3%的中！」を顧客に見せても「で、いくら儲かったの？」で終わる
- SNS映えする実績提示（払戻票の画像、残高推移グラフ）が皆無

#### 欠陥 3：購入動線が存在しない

現在のシステムにnote記事生成・投稿機能はない。  
予想→記事変換→有料ゾーン設定→投稿の全工程が手動。これでは毎週5〜6時間の追加作業が発生し、持続不可能。

#### 欠陥 4：無料フック（集客コンテンツ）がない

競馬予想の購買行動は「無料で当てさせてもらった → 信頼 → 課金」の順番。  
X（旧Twitter）に「今日の本命は3番◎」だけ投稿しても誰も読まない。  
**過去的中の強烈なスクリーンショット、解説、ドラマ性**が集客の核である。

#### 欠陥 5：競合との差別化要素が言語化されていない

「AIが予想します」は2024年に陳腐化した。  
UMALOGIの真の差別化は「**JRA公式データのみ使用・netkeiba一切不使用・オッズ補正済み期待値ベース絞り込み**」であるが、これは一度も顧客向けに説明されていない。

## Phase 1：商品の純化と自動記事生成（〜2026年6月末）

**目標**: 卍複勝モデルを主力商品として定義し、note記事の自動生成基盤を構築する

### 1-1. 卍複勝モデルの「商品化パッケージ」定義

- 推奨買い目: EV >= 1.0 の複勝のみ（三連単・馬連は除外）
- 1日の買い目点数: 最大5点（多点展開で薄まる印象を排除）
- 予算設定: 1点500円固定（顧客が追いやすい金額）
- KPI: 月次回収率110%以上を維持した週のみ記事を有料化

### 1-2. note記事自動生成スクリプト（最優先実装）

**実装ファイル**: `scripts/generate_note_article.py`

```
出力仕様:
  [無料ゾーン]
    - 本日の注目レース概要（会場・距離・芝/ダート）
    - モデルの自信度ランキング Top3（馬名はイニシャルのみ）
    - 過去1ヶ月の実績サマリー（的中率・回収率・最大配当）
    - 今週のモデル調整内容（学習日・特徴量更新の有無）

  [有料ゾーン（300〜500円）]
    - 全買い目（馬番・馬名・複勝オッズ・推奨投資額）
    - モデル根拠文（上位特徴量 Top5 を自然言語化）
    - 期待値と推定払戻の計算根拠
    - 本命馬のローテーション・前走分析コメント
    - 「この馬を消す理由」（2着候補の切り方）
```

**根拠文自動生成の仕様**（`src/ml/narrative_generator.py`）:

LightGBMのfeature importanceとSHAP値から自然言語コメントを生成する。

```
入力: race_id, horse_num, shap_values, feature_names
出力例:
  "3番△△△△は前走の上がり3Fが当コース基準値を8%上回り、
   卍モデルのスコアは0.73（当日出走馬中1位）。
   複勝オッズ2.1倍に対し期待値1.54と妙味十分。"
```

## Phase 2：実績の武器化とバイラル設計（〜2026年9月末）

**目標**: 過去の高額的中を「証拠として使える資産」に変換し、新規顧客の購買障壁を下げる

### 2-1. 的中実績カード自動生成

**実装ファイル**: `scripts/generate_hit_card.py`

Pillowを使いSNS映えする的中報告画像を自動生成する。

```
出力仕様:
  サイズ: 1200x630px（OGP最適サイズ）
  背景: UMALOGI ブランドカラー（ダーク+ゴールド）
  表示内容:
    - レース名・日付・会場
    - 的中券種・組み合わせ・払戻金額（大きなフォント）
    - モデル予想根拠コメント（1行）
    - 本日累計損益・回収率
    - QRコード（note記事URL）
```

### 2-2. 月次実績レポート自動生成

**実装ファイル**: `scripts/generate_monthly_report.py`

月末に自動集計し、note掲載用レポートとX投稿用サマリーを生成する。

```
集計内容:
  - 月間的中率・回収率（全体・モデル別・券種別）
  - 最大配当レース Top5
  - 収支グラフ（週次推移）
  - 前月比較
  - 「回収率が高かった条件」分析（芝/ダート・距離・開催場）
```

### 2-3. 無料/有料コンテンツの切り分け戦略

```
X（毎日更新・完全無料）
  → 前日予想のうち1点だけ公開（結果も翌日報告）
  → 高額的中時は当日即座に報告画像を投稿
  → 月次実績サマリーを定期ツイート

ウマニティ（毎週末・無料）
  → 全レース予想を投稿（EV順に並べ替え）
  → 無料で実績を蓄積→ランキング上位を目指す
  → 「続きはnoteで」の誘導文を各予想に追記

note（土曜・日曜朝 7:30 公開・有料）
  → 無料ゾーン: 会場概要・過去実績・本命馬のイニシャル
  → 有料ゾーン (300円): 全買い目 + 根拠文
  → 月定額マガジン (1,980円/月): 土日両日の全予想 + 月次レポート
```

### 2-4. 過去高額的中の遡及資産化

DBに蓄積済みの `prediction_results` から以下を抽出してnote記事化する。

```sql
-- Phase 2 開始時に一括変換する「実績記事ネタ」候補クエリ
SELECT r.race_name, r.date, r.venue,
       p.bet_type, p.combination_json,
       pr.payout, pr.profit,
       (pr.payout / p.recommended_bet * 100) AS roi
FROM predictions p
JOIN prediction_results pr ON pr.prediction_id = p.id
JOIN races r ON r.race_id = p.race_id
WHERE pr.is_hit = 1
  AND pr.payout >= 10000
ORDER BY pr.payout DESC
LIMIT 20;
```

## 商用化における倫理・法務上の留意点

1. **「必ず儲かる」表現の禁止**: 競馬予想の販売に景品表示法が適用される。ROI数値は「バックテスト結果」であることを明記すること。
2. **過去実績の誇張禁止**: 1日の突出した利益（+87万円等）を「平均的な成績」として提示しない。月次・年次の正直な集計を常に添付する。
3. **資金管理の明記**: 推奨投資額と損失許容範囲を毎記事に記載する。
4. **note規約の遵守**: 競馬予想販売はnoteで許可されているが、「情報商材的な誇大広告」は規約違反になりうる。
